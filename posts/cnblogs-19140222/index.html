# Dify

本文整理并重排了在本地从源码启动 Dify 的完整流程，覆盖后端、Worker 以及前端（建议在 WSL2 Ubuntu 中运行）三部分，并补充在 Windows 环境下的常见问题与规避建议。

概览

  • 后端与中间件：Windows（或 WSL2）上运行 Docker 与 Python 服务
  • Worker：与后端同机运行（使用 Celery）
  • 前端：建议在 WSL2 Ubuntu 中构建与启动（Next.js）

环境准备

  • 操作系统：Windows 10/11 或 WSL2 Ubuntu
  • 基础软件：Git、Docker Desktop（启用 WSL2 集成）、Conda（Python 3.12）、OpenSSL
  • C/C++ 构建工具（如依赖需要编译）：Visual Studio 2022 生成工具（含 C++ 工作负载）
  • Node.js 与包管理：nvm、npm、pnpm

关于 Windows 绝对路径构建问题（Next.js standalone）

在 Windows 下构建后，web/.next/standalone 目录可能包含带有项目绝对路径的层级（例如 \github\dify_gat\dify\web）。这会影响 pnpm start 的启动路径。

常见问题与提示

  • C++ 构建工具缺失：uv sync 或某些包安装时报 C++ 相关错误，请安装 Visual Studio 2022 生成工具（含 C++ 工作负载）。
  • Docker 未启动或端口占用：确保 Docker Desktop 运行，必要时修改中间件或 API 端口设置。
  • WSL 路径与 Windows 路径差异：前端在 WSL 中构建，注意与 Windows 端共享目录的路径映射与权限。
  • Next.js standalone 绝对路径：如出现绝对路径嵌套，调整 package.json 的 start 脚本指向 standalone 真实路径。
  • 环境变量：请根据 .env.example 完整配置后端所需的密钥与第三方服务参数。
